# 验收矩阵与通过门槛

这些是将来要执行的用例，当前均不因存在这份文档而视为通过。每条证据绑定源 run_id 和实际 APK SHA-256；历史成功只供定位回归。

## 质量门槛

| 门槛 | 通过标准 |
|---|---|
| G0 基线 | 源快照、APK 副本、版本工具路径与哈希可追溯；历史验证与当前候选分离；可构建性单独记录 |
| G1 启动 | V01～V04 真机通过：原动画可见可听、比例正确、完整/跳过/失败三路均进入可操作菜单 |
| G2 中文试点 | L01～L03 在菜单一项 + 教学一条真机通过；已明确可兼容旧渲染组件的字体方案 |
| G3 中文测试版 | 文本清单冻结后逐行有翻译与覆盖，L01～L05、P01～P03 通过，未翻译项为零或有明确豁免 |
| G4 稳定体验 | S01～S04、所有实际游玩关卡的 P04、P05 及已登记严重缺陷关闭 |
| G5 冻结发布 | 最终同一哈希 APK 的 R01～R03 通过；版本说明列完整覆盖与未覆盖项，最终产物可回退 |

“可运行”“启动正常”“全部汉化”“所有关卡正常”分别需要自己的证据，不能相互代替。

## 用例

| ID | 操作/范围 | 通过标准与证据 |
|---|---|---|
| V01 | 冷启动完整播放，至少连续三次 | 与原 intro 帧参考/元数据核对画面、顺序、时长、音画和比例；记录录像或人工声音反馈；1/3/6/10/14/20 秒截图只是补充；排除首尾设计黑帧 |
| V02 | 播放中点按跳过、返回键 | 只切换一次，菜单可点，无残留声音/Quad/相机；不能把正常跳过做成丢失视频 |
| V03 | 调试候选中模拟准备失败、停滞或文件不可读 | 有界超时退出，无黑屏死锁；调试故障开关不带入最终版，不改原视频 |
| V04 | 视频中后台/锁屏/恢复 | 状态可恢复或合理退出，无重复播放；失败进入菜单；前台包名与记录对应 |
| L01 | 汉字、标点、动态数字和占位符 | 中文字符集合全覆盖，无方框、缺字、格式参数或控制符损坏；字库来自最终已审校文本，临时动态文本有覆盖方案 |
| L02 | TextMesh / 旧 GUIText / 图片文字 | 真机字形清晰、颜色/描边/透明正确，无翻转、缺失；不为汉化重做已恢复的英文度量 |
| L03 | 宽屏、刘海/手势边缘、安全区、不同长度文本 | 横屏不裁切、不重叠，换行自然；按钮视觉范围与实际热区对应 |
| L04 | 菜单、设置、章节、教学、HUD、结算与异常提示 | 每个文本 ID 有来源、中文、上下文、字体/图片入口、截图位置或合理豁免；用户可见文本无意外英文残留 |
| L05 | 语气与操作含义 | 忠实、克制的奇幻语气；动作/方向/按住/松手/点按准确；术语跨界面一致；不先验锁定尚未清点原文 |
| P01 | 菜单进入 Tutorial、提示与前进 | 不提前显示原版刻意隐藏的控件；教学按原流程触发，点按/松手可继续 |
| P02 | 鹰/野猪变身与飞行模式 | 解锁后左右屏按住/松手语义正确；按钮/倾斜模式按原设置工作；变身不丢状态 |
| P03 | 第一关危险、连续死亡复活、返回菜单 | 碰撞、触发、动画、角色/相机/声音/特效恢复，无相关异常 |
| P04 | 每章各关与最终关/Boss流程 | 从正常入口到完成推进，包括关键机关/形态、死亡/检查点、结算/下一关；逐关证据，场景加载不算通关 |
| P05 | 与原版视觉/节奏对照 | 尺寸、镜头、动画/粒子/声音和操作时序无明显回归；手感由人工对照，不能凭代码推断一致 |
| S01 | 已保存设置/进度，退出重开 | 确认写入后的数据一致；不承诺未触发保存的瞬时状态；保留用户原数据 |
| S02 | 保存后强制结束进程再打开 | 已提交保存不丢，场景/设置合理；记录实际保存时机及语义 |
| S03 | 菜单/关卡内后台、锁屏、恢复和音频中断 | 无后台误触、时间异常、双重声音、黑屏或形态卡住；原流程可继续 |
| S04 | 可用时在隔离测试存档验证空/旧/损坏档 | 先核实真实格式及迁移逻辑；备份后验证恢复，无崩溃/静默覆盖；无依据的旧版本不伪造兼容声明 |
| R01 | 同一最终候选完整回归 | V/L/P/S 对应覆盖记录、设备环境、日志可追溯；阻断和严重缺陷为零；无新增相关异常 |
| R02 | 稳态游玩、加载、变身/复活高频场景 | 用同设备/设置基线记录帧时间、卡顿、内存和温升体验；先测量再定预算，不无依据许诺 120fps |
| R03 | APK 签名、更新与恢复、安装包内容 | ARM64/GLES3、21 场景顺序、原 intro 校验值保留；相同包名与签名可升级、保存保留；拒绝为安装成功卸载清数据 |

开发构建与拟交付构建如有差异，必须分别记哈希并回归最终那个；目前构建器硬编码 Development，不能只写“release”文件名便当正式构建。跨电脑注意 Android 默认 debug keystore 不同会影响覆盖安装，先核对证书；不上传私钥，不以卸载处理签名冲突。

V03 故障注入是有意的例外：用单独调试候选执行，记录它的 APK 哈希、故障开关差异与错误处理代码版本；最终候选核对相同错误处理逻辑及无故障开关，再重测正常完整播放/跳过/菜单路径。最终验证表引用 V03 的调试证据并标明环境，不虚构最终包上做过故障注入，也不为同哈希要求把故障开关留进交付版。

## 缺陷等级与回归范围

- P0：无法启动/游玩、存档损坏、关键操作不可用、无法正常推进；立即处理。
- P1：严重影响画面/音效/阅读/教学、频繁卡顿或严重生命周期错误；当前里程碑必须解决。
- P2：轻微排版或表现差异；记卡排期，不插入无关修改。
- P3：额外创意和新功能；后续清单，用户未要求时不扩大原版玩法。

文字改动测相关界面和字库；视频改动测 V01～V04 与菜单；字体/共享适配层改动扩大到所有消费界面；存档/场景流程或碰撞兼容改动复测受影响完整流程。每次合并做 P01～P03 冒烟，完整全关卡在首轮和发布前做覆盖，其他轮按风险抽检。测试不能执行时保持 not_run/blocked 或 waiting_device，绝不以阅读代码替代。
